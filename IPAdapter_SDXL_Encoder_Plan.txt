SDXL IP-Adapter Minimal Encoder Plan
====================================

Goal
----
Replace the current `sdxl.ip_adapter.encode` implementation with a minimal
encoder that creates `ip_adapter_image_embeds` without loading the full SDXL
text-to-image pipeline.

The current encode step uses `load_text2img_pipeline(...)`, which loads SDXL
UNet, VAE, text encoders, and other generation components before encoding the
IP-Adapter reference image. This still causes a large VRAM spike. The minimal
encoder should load only the components needed to produce image embeds.


Current Workflow Shape
----------------------
The workflow shape should remain unchanged:

1. `sdxl.ip_adapter.encode`
   - Input: reference image and adapter settings.
   - Output: ephemeral `e*.pt` embed artifact.

2. `sdxl.text2img`
   - Input: `ip_adapter.image_embeds: "@ip_embeds.image_embeds"`.
   - Render loads IP-Adapter with `image_encoder_folder=None`.
   - Render uses precomputed `ip_adapter_image_embeds`.

No frontend contract change should be needed after the minimal encoder swap.


V1 Scope
--------
Support only the current default SDXL base IP-Adapter:

- adapter model: `h94/IP-Adapter`
- subfolder: `sdxl_models`
- weight name: `ip-adapter_sdxl.bin`

Explicitly reject for v1:

- IP-Adapter Plus variants
- FaceID variants
- multiple IP-Adapters
- custom projection formats that require hidden states

The artifact format should keep `adapters: [...]` metadata so multi-adapter
support can be added later without changing the high-level contract.


Minimal Components Needed
-------------------------
For the base SDXL IP-Adapter, embed generation should need only:

- `CLIPVisionModelWithProjection`
- `CLIPImageProcessor`
- the IP-Adapter state dict, loaded on CPU for metadata/shape validation
- the reference image
- CFG mode: `guidance_scale > 1.0`

It should not load:

- SDXL UNet
- SDXL VAE
- SDXL text encoders
- SDXL tokenizers
- SDXL scheduler


How Diffusers Structures This
-----------------------------
Diffusers `prepare_ip_adapter_image_embeds(...)` does two relevant things:

1. It checks the IP-Adapter image projection layer type.
   - Base adapter uses `ImageProjection`.
   - Plus-style adapters use hidden states.

2. For base adapter, it calls:
   - `image_encoder(pixel_values).image_embeds`
   - creates zero negative image embeds
   - if CFG is enabled, concatenates negative then positive embeds

The minimal v1 encoder can reproduce this base-adapter behavior directly.


Proposed Implementation
-----------------------
Update `backend/sdxl_ip_adapter_pipeline.py`.

Replace the current full-pipeline encode path:

    pipe = load_text2img_pipeline(base_model)
    IpAdapterManager.load(...)
    IpAdapterManager.prepare_image_embeds(...)

with a minimal path:

1. Resolve/download adapter weights.
   - Use Diffusers/Hugging Face helper APIs where practical.
   - Load the adapter state dict on CPU.

2. Validate base adapter shape.
   - Require `state_dict["image_proj"]` to contain `proj.weight`.
   - Reject other projection layouts with a clear error:
     `Only the base SDXL IP-Adapter is supported by the minimal encoder.`

3. Load CLIP vision image encoder only:

    CLIPVisionModelWithProjection.from_pretrained(
        ip_adapter_model,
        subfolder=f"{ip_adapter_subfolder}/image_encoder",
        torch_dtype=torch.float16,
    )

4. Create `CLIPImageProcessor` with the encoder image size.

5. Move image encoder to CUDA.

6. Encode reference image:

    pixel_values = image_processor(image, return_tensors="pt").pixel_values
    pixel_values = pixel_values.to(device="cuda", dtype=torch.float16)
    image_embeds = image_encoder(pixel_values).image_embeds
    negative_image_embeds = torch.zeros_like(image_embeds)

7. Match Diffusers embed shape:

    single_image_embeds = image_embeds[None, :]
    if do_classifier_free_guidance:
        single_negative_image_embeds = negative_image_embeds[None, :]
        single_image_embeds = torch.cat(
            [single_negative_image_embeds, single_image_embeds],
            dim=0,
        )
    ip_adapter_image_embeds = [single_image_embeds.cpu()]

8. Save via existing `save_ip_adapter_embeds_artifact(...)`.

9. Release image encoder and call `cleanup_memory()`.


Metadata To Save
----------------
Keep the existing embed artifact format:

    {
        "format": "synthengine.sdxl.ip_adapter_image_embeds.v1",
        "family": "SDXL",
        "embeds": [tensor_for_adapter_0.cpu()],
        "metadata": {
            "base_model": model,
            "adapters": [
                {
                    "model": "h94/IP-Adapter",
                    "subfolder": "sdxl_models",
                    "weight_name": "ip-adapter_sdxl.bin",
                    "scale": 0.6
                }
            ],
            "do_classifier_free_guidance": true,
            "num_images_per_prompt": 1
        }
    }


Render-Side Behavior
--------------------
Keep the current `sdxl.text2img` render-side behavior:

- load embed artifact
- validate metadata
- load IP-Adapter with `image_encoder_folder=None`
- pass `ip_adapter_image_embeds` to the pipeline

No render-side change is expected for the minimal encoder.


Tests
-----
Add or update focused tests:

1. Minimal encoder unit test
   - Patch state-dict loading.
   - Patch `CLIPVisionModelWithProjection.from_pretrained`.
   - Patch `CLIPImageProcessor`.
   - Assert no `load_text2img_pipeline(...)` call happens.
   - Assert saved embed artifact contains one tensor list item.

2. Unsupported adapter projection test
   - Provide a fake non-base `image_proj` state dict.
   - Assert a clear v1 unsupported error.

3. Existing workflow tests
   - Keep `sdxl.ip_adapter.encode` task contract tests.
   - Keep `sdxl.text2img` `image_embeds` consumption tests.


Validation Commands
-------------------
Run:

    .\.venv\Scripts\python.exe -m pytest testing/test_ip_adapter_embeds_artifacts.py testing/test_sdxl_controlnet_workflow.py testing/test_sdxl_ip_adapter_pipeline.py -q
    .\.venv\Scripts\python.exe -m compileall backend


Expected Result
---------------
The encode step should have much lower peak VRAM because it no longer loads
full SDXL generation components. It will still use VRAM for the CLIP vision
encoder while creating embeds.


Open Questions
--------------
1. Should minimal encode run on CPU as a fallback if CUDA is unavailable?
2. Should Plus/FaceID support be added later by reproducing hidden-state embed
   preparation?
3. Should multi-IPAdapter support be added after v1 by allowing an adapter list
   and storing multiple embed tensors in order?
